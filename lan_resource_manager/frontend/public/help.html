使用帮助

本页面说明如何在不使用 AI agent 的情况下，通过“模块构建部署”完成开发槽集成、main 构建、测试部署与正式容器准备。

平台不会直接发布正式环境。正式环境页只提供单模块受控入口；每次正式执行仍需独立确认。本轮推荐停在“不可变 bundle 已就绪”。

推荐完整流程

1. 开发者在 A–H 槽提交、推送并 handoff 2. 打开“模块构建部署”，刷新状态 3. 输入页面显示的 INTEGRATE <main-sha>，点击“合并全部开发槽代码” 4. 等待批次 PR、main CI、不可变 bundle 和自动测试部署完成 5. 输入 ALIGN <main-sha>，对齐全部安全开发槽 6. 如需完整确认，输入 TEST ALL <bundle-sha>，部署测试环境全部模块 7. 确认“可信 bundle 已就绪”，即可作为以后正式环境部署候选；不要在本流程点击正式执行

状态与阻断

  • 脏工作区：槽内有未提交文件。平台不会提交、覆盖或删除，需开发者先处理。
  • 待合入：槽仍在分支上且 head 尚未被 main 包含。先完成 push/handoff 和集成。
  • 失败阻断：冲突、CI、构建或测试部署失败。修复原因后，在失败卡片输入界面给出的 RETRY <batch>，从同一批次安全重试；只有被更新 main 安全超越的旧测试失败会自动收敛。
  • bundle 待构建：输入 BUILD <main-sha>。平台只接受当前远端 main 和完整可信 CI，不生成 build-only 包。
  • 配置漂移：输入 TEST CONFIG <main-sha>，平台先生成计划，再原子同步测试环境配置投影；该入口没有正式环境参数，也不会手动进入维护。
  • 回滚材料缺失：输入 REPAIR TEST ROLLBACK <current-sha>。平台再次读取测试 control-plane 当前 state 并锁定精确 SHA，由受控 recover 拉取并验证旧不可变 bundle，再核对已记录与运行容器 digest，补齐 checkout 和非敏感 release.env；不拉运行镜像、不重启服务、不改部署状态。

测试环境全部模块

若 main bundle 因 GPU attestation 缺失而阻断，可输入 GPU BUILD <main-sha>。“准备全部 GPU 正式候选容器”会并行触发 8 个实际镜像构建，以同一 main SHA 形成 9-profile 完整 manifest，再重放模块 bundle。操作可从已经存在且具有成功 exact-SHA workflow 的镜像继续，不重复覆盖不可变 tag；它只准备容器，不创建 RunPod/LAN Pod，也不部署正式环境。

“部署测试环境全部模块”只接受发布策略中适用于 test 的模块精确全集，并把它们组成一次原子 release.py plan → deploy，使用短效 token、精确 SHA、digest、迁移与配置门禁。远端历史会在一次受限连接中读取；尚未部署过的模块只有被策略明确标为首次 artifact 才能加入。平台不接受模块子集、任意 service 或正式环境批量部署；失败时整次事务按发布器补偿，修复后可幂等重跑。

正式容器准备完成的判定

  • 远端 main 为完整 40 位 SHA，受保护 CI 成功。
  • 页面显示“可信 bundle 已就绪”。
  • bundle 中所有命中 artifact 都是 digest-pinned，并记录 OCI revision/checksum。
  • 测试环境适用模块已更新并通过发布器 smoke/evidence。

失败后如何处理

先等待页面中的操作进入“失败”或“已回滚”，不要同时启动另一条部署。模块构建部署会显示失败阶段和脱敏后的末行诊断；修复条件后，按页面给出的精确确认文字重试。若显示正在回滚或恢复，应等待验证完成，避免多个进程写同一个测试事务。重试 Pages 时会先验证现有 canonical SHA 与 runtime revision，完全匹配就安全复用，不会重复上传。

安全边界

平台不提供自由 shell、自由 service、跳门禁、正式环境回滚/恢复、任意配置 apply、GPU 节点批量操作或 Docker Socket。测试回滚材料修复是固定、无运行态变更的受控动作。Web 进程不读取 GitHub、云 SSH、GHCR 或 Pages 凭据；写操作由隔离 runner 的固定动作白名单执行并记录来源。
