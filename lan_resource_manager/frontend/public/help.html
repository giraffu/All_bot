模块构建部署帮助

平台只协调你明确选择的开发槽和模块，不查询 CI、bundle 或测试批准。

正式环境可以从管理后台执行，但必须选择精确模块、已有 digest 产物并输入页面给出的正式确认短语。页面不会自动发布。

开发槽

1. 开发任务在 A–H 完成 commit、push 和 handoff。 2. 点击“扫描槽位与模块”，勾选存在 pending handoff 的槽位。 3. 输入 INTEGRATE A,C <main-sha> 一类页面短语，合入所选任务。 4. 冲突任务进入 needs-rebase；其它所选任务继续。 5. 合入后勾选槽位，输入 ALIGN A,C <main-sha> 对齐代码。

脏工作区、未 push/handoff 或未被 main 包含的任务不会被覆盖。对齐只触及所选 槽位。

模块构建

  1. 选择测试或正式环境，勾选模块。
  2. 输入页面显示的 BUILD module-a,module-b <main-sha>。
  3. 构建完成后确认页面出现每个模块的精确 repository@sha256:digest。

构建只处理所选模块和必要 base；不会因为支付模块触发 GPU、Dashboard 或其它 业务模块。

部署

  • 测试环境每次选择 1–2 个模块，适合人工打开功能检查。
  • 正式环境可以多选；runner 仍逐模块执行，单个失败会停止后续模块并保留结果。
  • GPU 模块必须单独选择，并填写 LAN/RunPod 与 exact slot。
  • 未配置 test 实例的模块只会出现在正式环境列表。

输入 DEPLOY TEST module-a,module-b 或 DEPLOY PROD module-a,module-b 后执行。发布器只替换目标模块， 健康检查失败只回滚该模块；数据库 migration 不自动 downgrade。

安全边界

平台不提供自由 shell、自由 service、批量 GPU 操作或 Docker Socket。Web 进程不读取 Git、云 SSH、GHCR、Docker 或 Pages 凭据；隔离 runner 只接受固定 action，并记录来源 IP 与 operation 结果。
