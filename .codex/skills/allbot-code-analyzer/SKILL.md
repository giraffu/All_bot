# AllBot 静态代码分析与质量评估技能 (Code Analyzer)

此技能专为修仙主题工作台（All_Bot）量身定制。当你收到用户关于“代码静态分析”、“质量评估”、“检测死代码/坏味道”、“架构审查”等请求时，必须严格遵守以下步骤与规范进行操作，**保证静默执行、只读不写，且强制清理临时文件**。

## Workflow Instructions

当你被触发以执行系统代码静态分析与质量评估任务时，请严格按照以下标准化步骤操作：

### 1. 静态代码分析（静默执行）
- **分析范围**：对项目系统所有代码进行全面的静态扫描与评估。
- **执行要求**：在此期间仅做代码读取、逻辑分析与记录，**绝对不要修改任何现有代码或功能**。请将扫描和检测到的问题暂存到专用的临时文件或内存中，**不要在对话窗口中打印长篇的原始代码或中间检测结果**。
- **重点检查维度**：
  1. **死代码检测**：识别未被调用的函数、类、变量和未使用的导入语句。
  2. **注释清理**：标记过时、错误或误导性的注释，包括 TODO/FIXME 等遗留注释。
  3. **导入优化**：检查未使用的 import、循环依赖、冗余导入和导入顺序问题。
  4. **作用域分析**：识别变量作用域冲突、全局变量滥用、闭包问题。
  5. **代码重复**：通过逻辑相似度检测找出可合并的重复逻辑和复制粘贴代码。
  6. **性能问题**：标记低效算法、N+1 数据库查询、内存泄漏风险、不当的同步阻塞操作。
  7. **架构问题**：识别违反分层原则（如 Core Isolation）、过度耦合、违反单一职责的模块。
  8. **代码坏味道**：过长的函数/类、过深的嵌套、过多的参数、复杂的条件判断。

### 2. 质量评估与重构建议
基于临时收集的数据，进行深度汇总和定级：
- **优先级分类**：将所有问题按严重程度分为 `Critical`（致命风险）、`High`（高风险）、`Medium`（中等优化）、`Low`（低优先级优化）四个级别。
- **量化指标评估**：计算并提供全局宏观指标，如：估计的代码重复率、死代码比例、平均圈复杂度等。
- **架构级建议**：针对检测出的“架构问题”，提供可落地的重构建议与方向。

### 3. 报告生成与无痕清理（核心要求）
- **生成报告**：输出一份结构清晰的 Markdown 分析报告，必须包含：
  - 分析时间范围与涵盖的核心目录
  - 全局质量量化指标总览（重复率、死代码比例、复杂度等）
  - 核心问题清单：按优先级降序排列，每个问题必须包含**文件路径、行号、问题类型、严重程度、具体描述**
  - 架构优化与重构建议汇总
- **保存文件**：将报告命名为 `code_analysis_report_<yyyyMMdd_HHmm>.md`，使用 UTF-8 编码，写入到项目根目录的 `logs/` 文件夹下。此文件无需提交 Git。
- **清理中间产物**：**强制要求**在报告成功写入磁盘后，立即通过 shell 命令彻底删除步骤1中产生的所有临时分析缓存、切片或暂存数据。
- **最终输出**：向用户回复时，仅需提示“报告已生成完毕”，给出文件的绝对路径，并简要总结全局量化指标与 Critical 级核心风险即可。**严禁输出大段代码或中间检测细节。**
