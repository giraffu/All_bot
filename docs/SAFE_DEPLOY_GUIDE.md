## 🔄 正式环境脚本执行流程解析 (Step-by-Step)

`safe_deploy.sh` 当前分为 9 个自动化步骤，全程无需人工干预：

### 1️⃣ 开启系统维护模式
- **原理**：在主机器人容器 (`tg-bot`) 内部创建一个 `/app/MAINTENANCE` 文件。
- **效果**：机器人将立即进入维护模式，拒绝接收用户提交的新生图/生视频任务（不影响常规查询和菜单浏览），从源头切断增量任务。

### 2️⃣ 智能监控 Redis 活跃队列
- **原理**：注入 Python 脚本，轮询检查 Redis 中的 `active_tasks` 哈希表长度。
- **效果**：脚本会每隔 10 秒检测一次，直到当前正在被 Comfy Agent 处理的所有任务全部生成完毕。这保证了用户已经付款并排队的任务不会因为重启而丢失。

### 3️⃣ 僵尸任务与并发锁清理

### 4️⃣ 执行数据库迁移

- **效果**：数据库结构在服务重建前已处于目标版本，不再依赖“容器启动后手动迁移”。

## 💡 常见问题与排障 (Troubleshooting)

**Q1: 脚本卡在第 2 步（监控活跃队列）很久不动怎么办？**
- **原因**：可能有一个耗时极长的视频任务正在生成，或者有底层 Worker 已经宕机导致任务永远无法完成（变成僵尸任务）。
- **解决办法**：
  1. 打开一个新的终端，使用 `docker logs -f <对应的comfy-agent容器名>` 查看底层 Worker 是否还在工作。
  2. 如果确认 Worker 已经死机卡死，你可以手动在 Dashboard 或者 Redis 中清理该僵尸任务，脚本检测到数量归零后会自动继续往下执行。

**Q2: 执行时提示 `docker-compose: command not found`？**
- **原因**：您的系统可能使用的是新版 Docker 插件 `docker compose`（不带连字符）。
- **解决办法**：可以手动修改 `safe_deploy.sh` 脚本，将所有的 `docker-compose` 替换为 `docker compose`。

**Q3: 为什么 CS Bot (智能客服) 没有被更新？**
- **原因**：CS Bot 属于相对独立的子模块，为避免非必要的中断，默认未加入此脚本的全局重建流中。
- **解决办法**：如果您的更新涉及了 CS Bot，请在部署完成后手动执行：
  ```bash
  cd cs_bot && docker rm -f cs-bot && docker-compose up -d --build
  ```
