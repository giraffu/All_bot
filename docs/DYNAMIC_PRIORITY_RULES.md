# 动态优先级调整规则讨论稿

## 1. 背景与目标

目前系统采用基于“用户身份组”的静态优先级机制（金丹 > 筑基 > 练气 > 凡人）。然而，随着部分高频用户（单日调用 200+ 次）的出现，静态优先级可能导致以下问题：
1.  **资源独占**：高频高等级用户可能长时间占用计算队列，影响其他用户的正常体验。
2.  **缺乏调节**：无法对“刷单”或过度使用行为进行温和的系统级调节。

**目标**：引入“每日调用疲劳度”机制，实现优先级的动态衰减。保障高等级用户的基础权益，同时兼顾系统的整体公平性。

## 2. 核心规则设计

### 2.1 基础概念
*   **基础优先级 (Base Priority)**: 由用户当前的修仙境界决定（金丹=3, 筑基=2, 练气=1, 凡人=0）。
*   **动态优先级 (Dynamic Priority)**: 实际提交给任务队列的优先级。计算公式：`动态优先级 = max(0, 基础优先级 - 疲劳惩罚)`。
*   **日重置**: 每日 00:00 (服务器时间) 重置调用计数。

### 2.2 阈值与降级模型 (Threshold Model) - 修订版 V2

根据反馈，对高等级用户的“舒适区”进行了收缩，避免资源被过度占用。

| 用户身份 (基础Pri) | **舒适区 (无损)** | **繁忙区 (降级 -1)** | **拥挤区 (降级 -2)** | **限制区 (降级 -3/保底0)** |
| :--- | :--- | :--- | :--- | :--- |
| **金丹期 (3)** | **0 - 50 次**<br>(保持 Pri 3) | **50 - 100 次**<br>(降为 Pri 2) | **100 - 200 次**<br>(降为 Pri 1) | **> 200 次**<br>(降为 Pri 0) |
| **筑基期 (2)** | **0 - 25 次**<br>(保持 Pri 2) | **25 - 50 次**<br>(降为 Pri 1) | **> 50 次**<br>(降为 Pri 0) | - |
| **练气期 (1)** | **0 - 15 次**<br>(保持 Pri 1) | **> 15 次**<br>(降为 Pri 0) | - | - |
| **凡人 (0)** | **始终 Pri 0** | - | - | **> 10 次**<br>(建议限制) |

### 2.3 规则解读 (修订后)

1.  **金丹期的特权 (收紧)**：
    *   **前 50 次**：享有最高优先级 (Pri 3)。这对于绝大多数正常使用的核心用户已经足够。
    *   **50-100 次**：降级为 Pri 2 (筑基水平)。如果用户开始高频使用，优先级会迅速对齐到中等水平。
    *   **100-200 次**：降级为 Pri 1 (练气水平)。此时已进入“重度使用”区间，资源分配向普通用户倾斜。
    *   **> 200 次**：降级为 Pri 0 (凡人水平)。防止脚本或极端滥用。

2.  **筑基期的平衡 (收紧)**：
    *   **前 25 次**：保持 Pri 2。这覆盖了日常轻度娱乐的需求。
    *   **25-50 次**：降级为 Pri 1。
    *   **> 50 次**：降级为 Pri 0。一旦超过 50 次，即视为过度活跃，不再享有优先权。

3.  **练气期的限制 (微调)**：
    *   **前 15 次**：保持 Pri 1。作为入门用户，15次足够体验功能。
    *   **> 15 次**：降级为 Pri 0。

4.  **凡人的基准**：
    *   始终维持最低优先级 Pri 0。

## 3. 场景模拟 (Scenario Simulation)

*   **场景 A (高峰期)**:
    *   **金丹大佬 A** 今天已经跑了 150 张图。当前优先级 = **2**。
    *   **筑基新秀 B** 今天刚跑第 5 张图。当前优先级 = **2**。
    *   **结果**: A 和 B 在队列中优先级相同，按提交时间先到先得。

*   **场景 B (深夜爆肝)**:
    *   **金丹大佬 A** 跑了 250 张图。当前优先级 = **1**。
    *   **练气萌新 C** 刚起床跑第 1 张图。当前优先级 = **1**。
    *   **结果**: A 和 C 优先级相同。大佬虽然充值/活跃度高，但因过度占用资源，此时需让位于轻度使用的萌新。

*   **场景 C (极端情况)**:
    *   **金丹大佬 A** 跑了 400 张图。当前优先级 = **0**。
    *   **凡人路人 D** 跑第 1 张图。当前优先级 = **0**。
    *   **结果**: 众生平等。

## 4. 扩展讨论 (Optional)

1.  **排队权重 (Queue Weight)**:
    *   如果优先级相同，是否需要进一步区分？例如 Pri 0 内部，是否允许金丹用户比凡人稍快一点？
    *   *建议*: 暂不引入，保持逻辑简单。同优先级下 FIFO (先进先出) 最公平。

2.  **提示反馈**:
    *   当用户发生优先级降级时，是否通知用户？
    *   *建议*: 不主动弹窗打扰，但在“个人中心”或“排队状态”中可以显示当前动态优先级（如：`优先级: 2 (今日已用 120 次，略微下降)`）。

3.  **VIP 通道**:
    *   是否保留一个永远不降级的“元婴期”？（如有付费用户需求）。
