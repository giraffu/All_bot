# 测试与入口命名约定

## 1. 测试目录定位

- `tests/`
  - 当前主测试目录。
  - 新增的单元测试、focused tests、router/service/core 回归、集成测试统一放在这里。
  - 默认以可复用 fixture、稳定 seam 和 CI 可执行为准。
  - 根目录 `pytest.ini` 只收集该目录并使用 `--import-mode=importlib`，避免独立平台
    的同名 `test_main.py` / `test_config.py` 污染主套件模块命名空间。

- 独立平台测试
  - `media_enhance_platform/`、`lan_resource_manager/`、`lan_media_gallery/` 等可维护
    自己的依赖和测试入口；根套件不隐式递归收集它们。
  - 修改独立平台时必须在对应目录显式运行它自己的 focused tests，不能用根套件
    通过代替平台验收。

- `src/tests/`
  - 历史遗留测试目录已完成清理，本轮已整体迁回 `tests/`。
  - 若未来文档、脚本或缓存仍提到该目录，应视为待同步陈旧信息，而不是可继续放置测试的入口。

## 2. 命名规则

- 新测试文件统一使用 `tests/<domain>/test_*.py`。
- `src/tests/` 下不再新增新的 `test_*.py`。
- 文档、脚本、回归门禁中提到“测试入口”时，默认指向 `tests/`。

## 3. Telegram Bot 入口说明

- `src/bot_main.py` 是 Telegram Bot shared entrypoint。
- 生产与测试容器都启动 `src/bot_main.py`，真实运行模式由 `BOT_TYPE` 和对应 token 环境变量决定。
- 后续文档、部署脚本和排障说明中，统一将其描述为：
  - `Telegram Bot shared entrypoint (`src/bot_main.py`)`

## 4. 维护约束

- 新增测试时，先放 `tests/`，不要继续扩散 `src/tests/`。
- 历史脚本若仍引用旧 Bot 测试入口，应改为 `src/bot_main.py` 并显式设置 `BOT_TYPE`。
- 当 `Gallery` core/query seam、`task_core_submission.py` 默认依赖或 `user_persistence_service.py` 的 legacy 双 ID 分支发生变化时，优先补 focused tests，再更新热点门禁脚本与 workflow。
- 需要 PostgreSQL、Redis、对象存储或远端服务的测试使用 `integration` marker，并
  只在显式提供相应连接配置时运行；使用共享 `DATABASE_URL` 的数据库集成测试还需
  `ALLBOT_RUN_DATABASE_INTEGRATION_TESTS=1`，不能因 `.env` 默认值而误连开发者本机。
- 测试应直接 import 被验证的 canonical module。发布脚本偶然 import 的常量或
  helper 不是公共再导出接口，不能作为测试 seam。
