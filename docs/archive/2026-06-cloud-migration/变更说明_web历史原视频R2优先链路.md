# Web 历史原视频 R2 优先链路变更说明

## 1. 背景

当前 Web 端历史列表中，缩略图已经支持优先走 R2 公网 URL；但用户点击历史记录进入详情播放器时，原视频仍默认使用 MinIO 预签名 URL。

这会带来两个问题：

- 同一条历史记录中，列表封面与详情播放走了两套不同的媒体链路，行为不一致。
- 当 R2 中已经存在可直接访问的原视频时，详情播放器仍会优先请求 MinIO，增加后端签名链路依赖。

## 2. 目标需求

本次更新的目标是统一 `GET /users/history` 返回的媒体 URL 选择策略，使 Web 历史详情播放器能够优先直接播放 R2 上的原视频。

具体要求如下：

- `output_file_url` 与 `thumbnail_url` 保持一致的总体策略：R2 优先，缺失时回退 MinIO。
- 当 R2 中存在历史原视频对象时，`output_file_url` 直接返回 R2 公网 URL。
- 当 R2 中不存在对应原视频对象时，继续返回 MinIO 预签名 URL，保证兼容性。
- 缩略图现有逻辑保持不变，不因本次改动引入行为回退。

## 3. 改动范围

- 后端路由文件：`src/web_api/routers/users.py`
- 关键函数：`_pick_history_media_urls()`
- 相关测试：`tests/web_api/test_users_history_urls.py`

## 4. 实现方案

### 4.1 原视频 URL 选择策略

`_pick_history_media_urls()` 现在会先构造原视频的 R2 候选 key，并按以下顺序探测：

1. `history/{task_id}/original.{ext}`
2. legacy basename key，例如 `task-1.mp4`

若命中任意一个 R2 对象：

- `output_file_url` 返回对应的 R2 公网 URL

若都未命中：

- `output_file_url` 回退为 MinIO 预签名 URL

### 4.2 缩略图 URL 选择策略

缩略图逻辑维持原有行为，不做语义改变：

1. 优先探测历史缩略图 R2 key
2. 再探测 legacy 缩略图 key
3. 若 R2 不存在但 MinIO 中存在缩略图对象，则返回 MinIO 预签名 URL
4. 若都不存在，则返回空字符串

### 4.3 接口行为变化

本次改动后，`GET /users/history` 返回的 `output_file_url` 不再固定为 MinIO 预签名 URL，而是变为：

- 命中 R2 时返回公网 R2 URL
- 未命中 R2 时返回 MinIO 预签名 URL

因此，Web 端历史详情播放器在大多数已完成热缓存或已同步到 R2 的场景下，会直接播放 R2 上的原视频。

## 5. 预期收益

- 统一历史列表封面与详情播放的媒体读取策略
- 降低详情播放器对 MinIO 预签名链路的默认依赖
- 在 R2 已具备资源的情况下，减少不必要的签名 URL 生成
- 提升历史播放链路的一致性与可预期性

## 6. 兼容性与回退策略

本次更新采用保守回退设计，不要求历史数据必须已经完成 R2 同步。

兼容性表现如下：

- 新历史数据如果已完成 `history/{task_id}` 路径同步，将直接命中 R2
- 旧历史数据如果仍使用 legacy basename key，也可继续命中旧 R2 对象
- 若 R2 中没有原视频对象，接口仍返回 MinIO 预签名 URL，不影响已有播放能力

因此该改动不会因为 R2 缺失而导致历史详情不可播放。

## 7. 风险评估

### 7.1 可接受风险

- `GET /users/history` 每条记录会新增一次原视频 R2 存在性探测，请求成本相比原逻辑略有增加。
- 当历史原视频命中 R2 时，返回值由私有 MinIO 预签名 URL 变为公网 R2 URL，属于接口返回语义变化，需要确认这符合产品预期。

### 7.2 已规避风险

- 当前 `/result` 策略已对 Web 视频收窄 MinIO 回退：图片仍可在 R2 未同步完成时走短签 fallback，视频继续 `pending_result` 等 R2，且延迟敏感路径使用 R2 公网 HEAD 快探测，避免大视频经 MinIO 代理拉流或慢 S3 API HEAD 导致前端 99% 网络失败。
- 缩略图回退逻辑未改动，避免影响已有列表展示。
- 保留 legacy key 探测，避免旧数据因 key 收口导致短时或长期 404。

## 8. 测试与验证点

相关测试应覆盖以下场景：

- 原视频命中 R2，`output_file_url` 返回 R2
- 原视频未命中 `history/{task_id}`，但命中 legacy R2 key，仍返回 R2
- 原视频未命中任何 R2 key，回退 MinIO 预签名 URL
- 缩略图命中 R2 时优先返回 R2
- 缩略图未命中 R2 但 MinIO 中存在对象时，回退 MinIO 预签名 URL

建议联调验证以下前端表现：

- Web 历史列表封面正常显示
- 点击闪回瓶详情后，播放器优先加载 R2 原视频
- 对于未同步到 R2 的旧历史，详情页仍可正常播放

## 9. 结论

本次更新的核心目的是让 Web 历史详情播放器与列表封面的媒体读链保持一致，统一为“R2 优先，缺失时回退 MinIO”的策略。

在不破坏现有兼容性的前提下，接口已能够优先返回 R2 原视频地址，满足“点进闪回瓶详情时优先直接播放 R2 原视频”的目标需求。
