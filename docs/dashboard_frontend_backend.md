# 管理后台系统架构梳理 (Dashboard System)

该项目的管理后台（Dashboard）采用前后端分离的架构，用于管理员对整个修仙机器人的用户、数据、财务和素材进行全方位监控与管理。

后台系统与 Telegram Bot 机器人共享**同一个 PostgreSQL 数据库**和**同一个 MinIO 存储服务**。

---

## 1. 后端架构 (Backend)

后端采用了 **FastAPI** 框架，旨在提供高性能、异步的 RESTful API。

*   **入口文件**: `dashboard/backend/main.py`
*   **运行端口**: 默认 `8000` 端口
*   **数据库连接**: 复用了 Bot 项目下的 `src.database.core` (SQLAlchemy 异步会话)，直接读取和操作 `users`, `history`, `user_logs`, `orders` 等核心表。

### 1.1 核心中间件与安全机制
*   **CORS**: 配置了跨域资源共享，允许前端应用访问。
*   **Auth Middleware**: 实现了一个自定义的 `check_auth_header` 中间件，除了 `/api/auth/login` 和 `/api/health` 等公开接口外，所有请求都必须携带 `Bearer Token`（JWT）。
*   **路由**: 独立的 `auth_router` 用于处理登录发牌逻辑。

### 1.2 核心 API 端点与功能
*   **`/api/stats` (全局统计面板)**: 
    *   执行复杂的 SQL 聚合查询，返回：总用户数、总生成数、灵石流通总量、今日活跃、今日生成量等。
    *   包含用于画图的分布数据：`today_type_distribution` (按生成模式分类统计)、小时级生成热度等。
*   **`/api/users` (用户管理)**:
    *   分页查询用户列表，支持排序。
    *   提供 PUT 接口修改用户的 `credits` (灵石)、`temporary_ingot` 等核心资产。
*   **`/api/history` (任务历史)**:
    *   查询全服的 AI 生成记录，关联了用户信息。
    *   **亮点**: 放弃了直接暴露本地静态文件，而是通过调用底层的 `storage.py` 生成 **MinIO 的 Presigned URL (预签名链接)** 返回给前端，提升了安全性和云端分离能力。
*   **`/api/logs` (操作审计)**:
    *   分页读取 `user_logs` 表，支持按日期和 `operation_type` (如：签到、消费、充值) 进行筛选。
*   **`/api/orders` & `/api/plans` (充值系统)**:
    *   管理 `membership_plans` (TON 支付套餐配置)。
    *   查看 `orders` (链上订单对账明细)。
    *   支持**后台手动赠送**套餐给特定用户的接口。

## 2. 前端架构 (Frontend)

前端采用了 **Vue 3 (Composition API) + Vite + Ant Design Vue** 的现代化技术栈。

*   **入口文件**: `dashboard/frontend/src/App.vue`
*   **状态管理**: 直接使用 Vue 3 的 `ref` 和 `computed` 进行轻量级状态管理。
*   **图表库**: 集成了 **ECharts** 进行各种数据大屏的渲染。

### 2.1 页面布局与导航 (Layout)
采用经典的侧边栏 (Sidebar) + 顶部栏 (Header) + 内容区 (Content) 结构。
侧边栏包含 6 大核心模块菜单：

#### 模块一：首页看板 (Home / Dashboard)
*   **顶部指标卡片**: 展示当前系统的核心宏观数据（总用户、总流水、今日活跃等）。
*   **实时队列监控 (`QueueStats`)**: 调用 `/api/status` 获取当前 AI 后端显卡排队的实时情况。
*   **可视化图表矩阵**:
    *   **分布图**: 生成类型分布 (饼图)、用户积分消耗分布。
    *   **趋势图**: 历史用户增长曲线 (支持切换 7天/30天/半年)、日均生成量柱状图、累计分时生成热度图。

#### 模块二：用户管理 (User Table)
*   展示所有用户的详细列表，包含境界、积分、邀请人数等。
*   支持直接在表格中**给指定用户充值灵石**或修改签到天数。
*   提供“查看历史”按钮，点击弹出一个 Modal 模态框，展示该用户的全部生成历史记录。

#### 模块三：历史生成 (History Table)
*   全服 AI 生成任务的时间轴列表。
*   **渲染逻辑**: 调用后端接口获取数据的同时，拿到 MinIO 的临时访问链接 (`preview_url`)，直接在前端渲染生成的图片或视频。

#### 模块四：操作日志 (Log Table)
*   系统的对账与排错中心。
*   表格展示每一次灵石的增减情况，通过不同颜色标识操作类型（如充值为绿色，消费为红色）。
*   支持复杂的组合条件搜索。

#### 模块五：充值系统 (Recharge System)
*   **订单监控**: 查看全站用户的 TON 区块链充值订单（成功/失败/哈希值）。
*   **套餐管理**: 配置 `membership_plans`，即修改小程序前端展示的“内门、核心、真传”套餐的标价和赠送额度。
*   **手动补单**: 供管理员给特定 Telegram ID 直接下发指定套餐。

#### 模块六：模板共建 (Template Manager)
*   审核用户通过 Bot 发送的“模板共建”素材。
*   管理员可以预览、批准或拒绝，批准后可能会通过后端脚本自动同步到 MinIO 的公共模板桶中供全服使用。

### 2.2 核心特性与交互设计
*   **自动刷新与轮询**: 切换 Tab 时会自动触发 `refreshData()` 重新拉取最新数据。
*   **全局搜索**: 顶部栏提供了一个全局搜索框，支持输入 `Task ID` 直接定位到具体的生成任务弹窗。
*   **鉴权与路由守卫**: `App.vue` 内部监听了原生的 `unauthorized` 事件（通常由 axios 拦截器触发），一旦 Token 失效立刻销毁状态并退回 `<Login />` 组件。
