# 本地数据分析平台提示词词义分析指南

本文档记录本地数据分析平台里提示词词元治理的长期口径，用于后续审查指定词元、同义映射、删除表、长词元拆解和模板候选槽位。它描述语义原则，不替代 `local_analytics_platform` 的代码实现细节。

## 1. 目标与边界

- 目标是把 prompt 里的自然语言内容整理成更少、更准、可审核、可下钻、可用于后续模板候选的标签。
- 规则只影响本地分析平台的词元物化结果，不修改原始 `history.prompt`。
- 指定词元、映射表、删除表更新后，需要 tokens-only 重建才会影响 `analytics_prompt_token_stats` 和 `analytics_prompt_token_prompts`。
- 页面上的低频阈值只是查询/展示过滤，不是物化写表阈值。
- 年龄、人群、风险相关发现词元应保留可见性，便于人工审核和治理；不要为了让词元表变干净而直接隐藏问题。

## 2. 当前数据层

核心规则表：

- `analytics_prompt_token_custom_terms`：指定词元表，记录需要稳定抽取的词元、分类、子分类、来源和备注。
- `analytics_prompt_token_alias_rules`：词元映射表，记录代表词元和同义词元列表。映射在抽取和长词拆解之后应用。
- `analytics_prompt_token_deleted_rules`：词元删除表，隐藏无标签价值、碎片、流程词、技术词或错误抽取。

物化与缓存表：

- `analytics_prompt_token_extract_cache`：按 prompt 和抽词版本缓存 raw tokens，不应用同义映射，便于改映射后复用抽词结果。
- `analytics_prompt_token_stats`：词元统计表，保存当前物化后的 token、scope、prompt_count、use_count、user_count。
- `analytics_prompt_token_prompts`：词元到 prompt 明细的倒排结果，支持查看抽屉和其它词元展示。
- `analytics_prompt_token_scope_summary`：scope 候选 prompt 数摘要，供列表 API 快速计算占比。

模板候选相关：

- `analytics_prompt_template_candidates`：只读模板候选汇总。
- `analytics_prompt_template_candidate_prompts`：模板下的 prompt 明细。
- `analytics_prompt_template_state`：模板候选刷新状态。
- `analytics_prompt_decomposition_saved_templates`：自由P图拆解页人工沉淀的优秀模板。

## 3. 标准处理流程

1. 先做只读审计。
   - 从当前前端等价 scope 导出可见词元，例如全局 `min_prompt_count=20`。
   - 按频次、分类、规则归属、疑似碎片、疑似宽泛词、疑似误映射分批。
   - 对需要判断语义的词元抽样真实 prompt，不凭词面想象。

2. 输出可复核报告。
   - 每条候选只能有一种主动作：`delete`、`alias`、`custom_term`、`split_or_rescue`、`move_category`、`keep`、`review_needed`。
   - 高置信项说明为什么改；低置信项进入人工审查清单。

3. 写库前备份。
   - 至少备份三张规则表：指定词元表、映射表、删除表。
   - 大批量治理应记录报告目录和变更摘要。

4. 事务写入和校验。
   - 同义词不能归属多个代表词。
   - 代表词不能同时作为其它代表词的同义词。
   - active 指定词元和映射规则必须有分类/子分类。
   - 空词、纯噪声、明显专名碎片不得进入 active 规则。

5. tokens-only 重建。
   - 规则改动只有重建后才会物化到词元表和详情抽屉。
   - 重建命令：

```bash
docker exec allbot-local-analytics-platform python -m app.refresh_prompt_vectors --tokens-only --statement-timeout-ms 3600000
```

6. 重建后复核。
   - 检查规则 `updated_at` 与状态 `applied_at` 是否一致。
   - 检查删除词是否还可见。
   - 检查代表词能否搜索到并下钻真实 prompt。
   - 若改动影响模板槽位，再刷新模板候选。

## 4. 分类体系与槽位

后续模板候选和标签治理优先使用以下大类：

| 分类 | 用途 | 示例子类 |
| :--- | :--- | :--- |
| `保持口径` | 原图/人物/背景/姿态/风格等一致性要求 | 人物一致、背景保持、原图保持 |
| `人物主体` | 人数、性别、年龄、族裔国别、关系角色、组合人群 | 人数、性别、年龄、族裔国别 |
| `身体部分` | 核心部位及带属性的部位标签 | 胸部、毛发状态、生殖器形态、手部、腿部 |
| `动作姿势` | 动作、姿势、身体状态和稳定运动语义 | 姿势、动作、身体状态 |
| `成人主题` | 成人语义、关系主题、器具道具、裸露变化等 | 关系主题、器具道具、裸露变化 |
| `服饰配件` | 服装、配饰、材质、穿脱变化 | 服饰、配饰、服饰变化 |
| `场景` | 真实场地、环境、空间对象 | 室内、室外、家具、地点 |
| `镜头构图` | 可复用的拍摄视角、画面距离、主体位置 | 视角、景别、画面空间 |
| `风格质量` | 风格、真实感、画风、质感等有效风格标签 | 写实、动漫、质感 |
| `表情情绪` | 明确表情、情绪或眼神状态 | 表情、情绪、眼神 |
| `外观特征` | 有辨识价值的外观状态，不含过宽颜色词 | 体型、妆容、显著特征 |

旧分类 `观测高频词`、`技术参数`、宽泛 `生成编辑` 不应作为 active 语义分类继续扩张。历史行如果保留，应 disabled 或迁移到新分类/删除表。

## 5. 词元治理原则

### 5.1 标签价值优先

词元最终是标签，不是分词结果的完整保留。以下内容通常不应作为独立可见标签：

- 过宽分类词：如单独的“动作”“人物”“身体”“背景”“镜头”“构图”“发色”“肤色”。
- 低信息颜色/状态：如单独的“黑色”“白色”“蓝色”“清晰”“细节”，除非和对象组成稳定复合标签。
- 技术和流程词：如模型名、采样、帧率、提示词强度、图片、视频、上传、生成流程。
- 缺前后缀碎片：如被长词误切出来的单字、半截词、数字/字母残片。

如果一个词只有和对象一起才有意义，应保留复合词或派生代表词，而不是保留孤立形容词。

### 5.2 基础部位和属性分开

核心部位有标签价值，但属性不能混进基础部位：

- `乳房` 是基础部位；尺寸/形态应拆为 `大胸`、`小胸`、`平胸` 等。
- `阴毛` 是基础部位；密度/状态应拆为 `有阴毛`、`无阴毛`、`浓密阴毛`、`稀疏阴毛` 等。
- `阴茎` 是基础部位；尺寸、颜色、形态应拆为独立属性标签。
- `阴道` 是基础部位；形态或状态短语若有稳定语义，应作为独立标签或映射到对应属性代表词。

不要把“大/小/颜色/密度/形态”的同义词直接塞进普通部位代表词。

### 5.3 长词元拆解与救援

长词元分三类处理：

- 可拆解：拆出多个有标签价值的基础词元或复合标签。
- 可归一：整词映射到更标准的代表词。
- 应隐藏：人名、账号、随机专名、句子碎片或无标签价值的长片段写入删除表。

例如，带稳定姿势含义的 `m型开腿/m形开腿/腿呈m形` 应归到 `m字开腿`；缺少前缀的碎片不要独立展示。`双腿大字型分开` 不应误映射到 `m字开腿`，应归入更准确的 `双腿分开` 或进入审查。

### 5.4 同义映射只合并同一概念

映射表用于同义、繁简、拼写、多语言和稳定隐晦表达的归一。它不应用来做过度概括：

- `露脸` 和 `不露脸` 是相反语义，必须分开。
- 基础部位和属性标签分开。
- `亚洲人`、`亚洲小男孩`、`黑人男孩` 是不同细粒度标签，不能为了减少数量全部合并到族裔大类。
- 年龄段、性别、族裔国别和组合人群可以并存，用于后续人工审核和筛选。

代表词优先使用标准中文名；外语、繁体、拼音、大小写变体进入同义词列表。

### 5.5 删除表不是垃圾桶

删除表用于隐藏“没有标签价值”的词元，不用于隐藏需要治理的问题。以下内容不应仅因为敏感或风险而删除：

- 明确年龄、人群、学生、数字年龄短语。
- 可能需要人工审核、封禁或安全策略判断的发现标签。

这些词应进入 `人物主体` 下的年龄、性别、族裔国别、组合人群或数字年龄分类，并通过映射表归一，供后续审核使用。

## 6. 年龄与人群发现口径

年龄/人群词元的用途是发现和审核，不是生成模板素材。模板候选或后续自动提示词生成如果涉及风险人群，必须单独做安全过滤。

建议分类：

- `人物主体 / 年龄`：儿童、少年、少女、年轻女性、中年男性、老年女性等年龄段标签。
- `人物主体 / 数字年龄`：从真实 prompt 命中的具体年龄短语，可映射到年龄段代表词，同时保留审计来源。
- `人物主体 / 性别`：女性、男性、男孩、女孩等有筛选价值的性别/称谓标签。
- `人物主体 / 族裔国别`：亚洲人、东亚人、中国人、台湾人、日本人、韩国人、黑人、白人等。
- `人物主体 / 组合人群`：族裔 + 年龄 + 性别等组合短语。组合标签保留独立粒度，不强行合并到大类。

具体年龄可按治理需求映射到年龄段代表词，但不要直接隐藏。对 `18y/23y` 等简写必须先用真实 prompt 样本确认语义，再决定是否归入数字年龄或进入审查。

## 7. 审计报告建议格式

只读审计目录建议包含：

- `visible_tokens_min20.csv`：等同前端词元表的当前可见结果。
- `token_rule_join.csv`：词元与指定词元、映射代表词、删除状态、分类的关联。
- `token_prompt_samples.jsonl`：每个待审词元 3-5 条真实 prompt 样本。
- `proposed_rule_changes.md`：给用户复核的建议。
- `batch_<range>_decisions.csv`：分批结构化决策。

决策字段建议固定：

```text
token, action, representative, aliases, category, subcategory, reason, confidence, sample_hashes
```

高置信阈值默认不低于 `0.90`。低于阈值或样本语义冲突时，不自动写库。

## 8. 写库前后校验

写库前校验：

```sql
-- 同义词不能归属多个 active 代表词
-- 具体 SQL 可按当前 schema 展开 unnest aliases 后 group by alias。

-- active 代表词不能作为其它 active 规则的 alias
-- 发现后应拆分、禁用或改代表词。

-- active 指定词元和映射规则不能缺分类
select count(*) from analytics_prompt_token_custom_terms
where enabled = true and coalesce(category, '') = '';

select count(*) from analytics_prompt_token_alias_rules
where enabled = true and coalesce(category, '') = '';
```

重建后复核：

- `analytics_prompt_vector_state` 中对应 token version 的 `applied_at` 应不早于规则更新时间。
- 删除表中的词元不应出现在 `GET /api/prompt-tokens` 可见结果。
- 代表词搜索应能看到合并后的 prompt_count 和真实 prompt 明细。
- `other_tokens` 应展示映射后的代表词，并同步应用删除表和低频阈值。

## 9. 模板候选口径

模板候选 v1 是只读聚合，不调用 LLM，不生成线上模板。它依赖词元分类和 scope：

- scope 由任务类别和可选附加模型决定。
- 模板 key 由 task scope、model key 和规范化槽位词元集合决定。
- 软删除词、技术流程词、低标签价值宽泛词不应进入模板槽位。
- `自由P图`、`自由P图 v2` 等编辑类任务默认强调主体对象和保持口径，再围绕动作姿势、成人主题、身体部分、镜头构图、风格质量等槽位形成候选。

模板候选刷新命令：

```bash
docker exec allbot-local-analytics-platform python -m app.refresh_prompt_template_candidates --statement-timeout-ms 3600000
```

仅当词元分类变更需要影响模板候选时才刷新；普通规则审查不必自动刷新。

## 10. 自由P图拆解页口径

“自由P图拆解”页是模板候选之前的人工浏览层，重点不是自动聚合，而是让人按标签筛真实 prompt、拆开结构、手工保存优秀模板。

- 当前 scope 固定为 `edit`，即“自由P图”。
- 只展示已经进入有效分类体系、且在当前 scope 下 `prompt_count >= 20` 的词元。
- 一级筛选组使用浏览友好的固定顺序：
  - `保持口径`
  - `场景`
  - `物品`
  - `表情`
  - `成人主题`
  - `动作姿势`
  - `画面风格构图`
  - `身体细节`
  - `外观特征`
  - `服饰配件`
  - `人物主体`
- 二级筛选直接复用指定词元/映射表里的 `category + subcategory`，不要为拆解页再发明一套孤立命名。
- `场景 + 家具` 归到 `物品`，`成人主题 + 器具道具` 也归到 `物品`；`镜头构图` 与 `风格质量` 合并显示为 `画面风格构图`；`身体部分` 在拆解页显示为 `身体细节`。
- 未分类词元不进入该页筛选器，避免继续放大脏标签。

优秀模板沉淀规则：

- 保存的是“当前浏览到的一条真实 prompt”，不是自动生成的新文案。
- 需要连同 `selected_tokens`、完整 prompt、分组后的 grouped tokens、uses/users/quality_score 一起落库。
- 保存优秀模板不影响词元规则，也不需要 tokens-only 重建。
- 词元规则变化后，拆解页会直接使用新的分类与映射重新展示；已保存模板保留当时的 prompt 文本和分组快照，用于后续人工整理。

## 11. 性能与运行备注

当前 tokens-only 重建已使用 raw token cache 和指定词元匹配器。近期基线中，全量缓存命中情况下 tokens-only 约 5 分钟，主要耗时在扫描 prompt 和写索引阶段。不要为一次小规则改动反复重建；可以先累积规则，再统一重建。

前端词元表翻页、规则表分页和详情抽屉依赖已物化统计表。若翻页变慢，优先检查：

- 是否误触发了规则表全量渲染。
- `/api/prompt-tokens` 是否使用 `include_filters=false` 快路径。
- scope summary 是否存在。
- 详情抽屉是否复用 stats 的 `prompt_count`，避免重新扫全量 prompt。

## 12. 已沉淀的关键判断

- `原图/参考图` 等保持语义可以归入 `保持口径 / 一致` 或更细的背景/主体保持口径。
- `m字开腿`、`深蹲`、`弯腰`、`内射`、`脏污`、`倒吊` 等是有标签价值的代表词，不应因形态像动作碎片而删除。
- `内凹穴` 是独立形态标签，不应直接合并到普通 `阴道`。
- `手脚无力` 应归 `动作姿势 / 身体状态`。
- `有阴毛` 应归 `身体部分 / 毛发状态`。
- 单字中文不一概删除；但来源多为误切或无独立标签价值时应软删除。
- 所有新增指定词元必须来自当前词元表或真实 prompt 样本，不为了“看起来完整”虚构词元。
