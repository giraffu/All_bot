# 04_BIZ_用户修为与身份权限体系

## 1. 业务定位

本体系把用户能力分为两条线：

- 修为境界：反映活跃度、签到与使用积累
- 会员身份：反映付费权益与高级能力准入

在当前实现中，这两条线不只影响任务优先级，也直接影响 Web 登录资格、视频档位、功能入口与会话续存。

## 2. 当前业务事实

- Web 登录并非全员开放。
- 允许 Web 登录的用户，需要满足“境界或身份”其中一项达到阈值。
- 用户即使已经拿到 JWT，后续若身份或境界下降，也会在 `get_current_user` 中被再次拦截。
- 因此权限体系已经从“发卡式授权”演进为“动态权限复核”。
- 身份过期会在 `PermissionIdentityPriorityService.get_user_identity()` 中自动视为 `外门弟子`；但少数接口若直接读取 `users.current_identity` 字段，仍需单独核对是否复用了动态身份口径。
- 排队优先级是“修为优先级 + 身份优先级”相加；新用户累计生成次数小于 2 时固定给 `+30` 新手优先级。
- `low_trust_free_tier` 是实时计算的内部低信任免费层标记：`checkin_count > 7`、自身无任何 `SUCCESS` 订单，且不满足高质量邀请者豁免时命中。高质量邀请者豁免以 `referrals` 真实邀请边为准：受邀用户数 `>100`，且有任意 `SUCCESS` 订单的受邀用户去重占比 `>3%`；手工赠送、礼品单和 0 元成功订单也计入受邀充值率。非低信任用户在原本新手/修为/身份优先级基础上额外 `+40`，低信任用户不拿这段加成；Gallery 提示词解锁不再按低信任免费层拦截。自身任意成功订单都会使用户不再命中该标记。
- 标准快速视频设置面板使用 `RESOLUTION_PERMISSIONS` / `DURATION_PERMISSIONS` 按“修为 + 身份”取并集；其他视频入口可能有独立规则，不能把该表误写成全站强校验。

## 3. 两条等级线的作用

### 3.1 修为境界

- 影响排队优先级与部分功能可见性。
- 是零氪或轻氪用户进入 Web 与高级功能体系的重要路径之一。
- 当前自动晋级最高到 `元婴期`；`化神期`、`炼虚期`、`合体期`、`大乘期`、`渡劫期` 只在 Web 准入 allowlist 中存在，没有自动晋级和专属视频/优先级规则。
- 修为刷新入口为 `PermissionIdentityPriorityService.refresh_user_group()`，晋级阈值使用严格大于 `>`，不是大于等于。签到服务在资格判定前也会调用该入口，以消除已持久化频道成员资格与旧 `user_group` 不一致造成的误拒。

### 3.2 会员身份

- 影响高级分辨率、长视频、隐藏高消耗节点等能力开放。
- 影响充值发货后的身份到期时间与跨级折算。
- 当前仍是 `内门弟子`、`核心弟子`、`真传弟子` 三层结构。
- 身份月卡来自 canonical membership plan；纯灵石套餐 `duration_days == 0`，只增加 `credits`，不改变身份。
- 返佣兑换身份已有代码路径和固定选项，但运行时同时受 `MEMBERSHIP_SETTLEMENT_V2_ENABLED` 与 `AFFILIATE_MEMBERSHIP_REDEEM_ENABLED` 控制；未开启时 Web API 返回 404。

### 4.3 叠加与例外

- Web 准入：`current_identity in WEB_ACCESS_ALLOWED_IDENTITIES` 或 `user_group in WEB_ACCESS_ALLOWED_GROUPS` 任一成立即可。
- 签到：先按持久化频道资格刷新修为；刷新后仍为凡人时，只有动态有效身份为 `内门弟子`、`核心弟子` 或 `真传弟子` 才能签到，外门仍须先入宗门。
- 标准快速视频：修为档位和身份档位取并集；例如 `练气期 + 核心弟子` 可显示 `1024p` 和 `10s`。
- 标准快速视频中 `1024p` 与 `10s` 互斥，选择其中一个时会自动避开另一个。
- LTX 视频设置当前硬编码 `1280x704`，时长显示 `5s`、`10s`、`15s`、`20s`，未按修为/身份做差异化。
- SCAIL-2 视频换脸 v10 固定 `512x896`，只开放 `5s=40` 灵石和 `8s=80` 灵石，未复用 `RESOLUTION_PERMISSIONS`。
- 低信任免费层例外：连续免费活跃、没有自身成功订单且缺少高质量邀请转化的用户不封号、不扣灵石；系统通过给非低信任用户统一 `+40` 的方式形成队列差距，低信任用户保留原本基础优先级但不获得该加成；Gallery 提示词解锁不再按该标记拦截。
- 高负载限制：提交入口先把公开/legacy 任务归一到对应 Worker 执行池，并读取 Central `/system/status.queue_pressure_by_worker_profile`。对 `外门弟子` 且修为为 `凡人` 或 `练气期` 的用户，仅当接纳本单后的 `projected_pending > 50 × max(健康且 enabled 的可接单 Worker 数, 1)` 时拒绝；零可接单 Worker 仍按 1 台保护容量允许最多 50 个 pending。`筑基期` 及以上或 `内门弟子` 及以上不受该限制；快照缺失、请求失败或任务未映射到已管理执行池时 fail-open，只保留原有个人并发限制。
- 并发限制：提交入口通过 `billing_core.check_concurrency_lock()` 按动态有效身份限制处理中任务数；外门/默认身份 `3` 个，内门 `5` 个，核心 `8` 个，真传 `12` 个，身份过期、未知身份或凡人低档均回落为外门 `3` 个。
- 收藏上限当前由 `users_history_mutation_service._get_favorite_limit_for_identity()` 按 `current_user.current_identity` 字段计算，未复用 `PermissionIdentityPriorityService.get_user_identity()` 的过期回落逻辑。

## 5. 与认证系统的耦合点

- Telegram 登录后，不是所有用户都能进入 Web。
- 密码登录同样要复用相同的 Web 准入校验。
- 改密、降权、身份过期都会影响既有会话是否继续有效。
- `get_current_user` 会重新读取用户统计与当前身份/境界，继续执行动态权限复核。

## 6. 与商业化系统的耦合点

- 身份月卡购买成功后，权限立即变化。
- 纯灵石套餐只变更 `credits`，不变更身份。
- 纯灵石 canonical 套餐：
  - `200 Star 直购`：¥30 / 1.99 TON / 200 Stars，到账 `600` 灵石。
  - `500 Star 直购`：¥70 / 4.99 TON / 500 Stars，到账 `1800` 灵石。
  - `1000 Star 直购`：¥120 / 9.90 TON / 1000 Stars，到账 `4000` 灵石。
- 返佣兑换灵石已经上线，固定套餐为 `1/3/6/10/15/20 USDT -> 130/390/780/1800/2700/4000` 灵石。
- 返佣兑换身份已有服务与接口，选项为 `内门弟子 30 天`、`核心弟子 30 天`、`真传弟子 30 天`，但运行时需要同时打开 `MEMBERSHIP_SETTLEMENT_V2_ENABLED` 与 `AFFILIATE_MEMBERSHIP_REDEEM_ENABLED`。

## 7. 代码口径索引

- `src/constants.py`：Web allowlist、标准视频档位、动态优先级、收藏上限、canonical 任务成本。
- `src/services/permission_identity_priority_service.py`：修为刷新、身份过期回落、Web 准入判断、优先级计算。
- `src/services/permission_growth_channel_service.py`：签到奖励、邀请处理、频道/宗门状态同步。
- `src/core/billing_core.py`：高负载提交限制、统一并发锁、扣费与退款入口。
- `src/services/membership_plan_catalog.py`：canonical 月卡与纯灵石套餐。
- `src/services/affiliate_redeem_rules.py` 与 `src/services/affiliate_redeem_service.py`：返佣兑换灵石/身份规则与幂等履约。
- `src/web_api/dependencies.py`：Web 请求动态权限复核。
- `src/web_api/services/users_history_mutation_service.py`：按 `users.current_identity` 字段限制收藏数量。

## 8. 文档维护口径

- 不要再把“Web 入口”写成金丹期以上专属固定规则，实际以代码中的允许组/允许身份集合为准。
- 不要把权限体系只描述成任务调度权重，它已经同时影响登录、会话、可用功能与前端展示。
- 不要把标准快速视频档位误写成所有视频入口的全局强校验；LTX、视频换脸等入口当前存在独立实现。
- 若修改 `src/constants.py` 中的 allowlist、档位或优先级规则，必须同步更新本文档表格。
