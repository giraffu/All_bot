# 业务板块分类与规范总览

## 1. 文档体系与命名规范

为确保系统的业务知识沉淀清晰可读、便于维护与溯源，系统将所有纯业务视角的文档（BRD、FSD、业务流程图、数据字典、操作手册等）统一收敛至 `docs/business/` 目录下。

### 1.1 命名规范
所有业务文档遵循以下命名格式：
**`[编号]_[文档类型]_[业务板块名称].md`**

*   **编号 (ID)**：`00` 表示全局/基建规范；`01`-`99` 表示具体业务板块序号。
*   **文档类型 (Type)**：
    *   `INDEX`: 业务板块总览与规范 (Index)
    *   `DICT`: 数据字典 (Data Dictionary)
    *   `BIZ`: 业务全景文档 (Business Overview，内聚包含需求、流程、接口与操作手册)
*   **业务板块名称 (Name)**：简短的中文板块名称。

*示例*：`01_BIZ_AI创作与生成板块.md`

### 1.2 统一文档结构要求 (适用于 `BIZ` 类型文档)
所有 `BIZ` 类型业务文档必须严格包含以下 6 个核心章节，以保障业务知识闭环：
1.  **业务需求说明书 (BRD)**：阐述该板块的核心价值、目标用户与商业逻辑。
2.  **功能规格说明书 (FSD)**：列举系统边界内的核心功能清单（如支持的生成参数、权限拦截点）。
3.  **业务流程图 (Flow)**：使用 Mermaid 绘制用户操作的端到端时序流或泳道图。
4.  **关键接口与数据契约 (API/Data)**：罗列前端或客户端对接的核心 API 契约或依赖的数据库字段。
5.  **用户操作手册 (Manual)**：提供给最终用户或运营人员的分步操作指南。
6.  **版本历史与溯源 (Changelog)**：记录核心业务逻辑的变更时间与责任人。
