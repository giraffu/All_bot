# 业务板块分类与规范总览

## 1. 文档体系定位

`docs/business/` 用于从业务视角沉淀系统板块、核心概念、跨板块口径与索引关系。它不是对技术实现的逐文件镜像，而是对“当前已上线能力”的业务归档层。

当前目录下的 `00_*` 文件承担两种职责：
- `00_INDEX_*`：板块导航、维护规则、跨板块同步提醒
- `00_DICT_*`：全局业务词汇表与核心数据契约

## 3. 总览层维护规则

### 3.1 什么情况必须改 `00_INDEX`
- 主营板块的“已落地范围”发生变化
- 某个支撑板块从次要能力演化为常驻主路径
- 某项旧流程被降级为兼容路径，需要避免误导后续开发

### 3.2 当前必须统一的全局口径
- 商业化板块不再只是“充值发货”，还必须包含 affiliate 返佣账本与返佣兑换灵石。
- 社区板块不再只是“投稿 + 点赞”，还必须覆盖评论、收藏与 Web `apply-context`。
- 用户权限板块不再只是任务优先级，还直接影响 Web 登录资格与会话有效性。
- AI 客服板块的现行实现是 `cs_bot + LangGraph + LM Studio`，不是旧式提示词优化器。

## 5. 文档维护声明
- `00_INDEX` 只维护板块边界与全局口径，不复制各 `BIZ` 文档的完整细节。
- 若某板块出现重大事实变更，应优先更新对应 `BIZ` 文档，再回填本总览索引。
- 若板块描述与代码现状冲突，以已落地代码和对应子模块文档为准，随后尽快修正文档。
