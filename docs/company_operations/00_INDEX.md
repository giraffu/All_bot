# 公司管理与财税运营知识库

## 1. 范围与分层

本知识库覆盖公司主体、证照、税务、资金、支付商户、会计账簿、供应商成本、
网站备案和 AI 服务合规。它分为三层：

1. Git 中的本目录保存稳定制度、字段口径、官方依据和操作清单，不保存秘密。
2. `${XDG_CONFIG_HOME:-~/.config}/allbot/company-operations/` 保存本机主体详情、
   真实凭据、当前办理状态、流水账和证据原件，目录权限为 `0700`、文件为 `0600`。
3. 支付宝、中国银行、电子税务局、产品数据库等外部系统保存交易和申报事实；
   本地资料是索引与会计解释层，不替代外部原始记录。

产品订单/灵石/affiliate 账本与公司法定会计账不是同一套账。前者回答用户权益，
后者回答公司资产、收入、成本、税负和银行余额；二者通过业务单号、支付渠道流水、
结算批次和银行入账进行勾稽。

## 3. 每月闭环

1. 从产品订单、支付宝/微信、中国银行和供应商分别导出当期原始数据，原件只读归档。
2. 以外部交易号和结算批次勾稽“订单 → 渠道交易/退款 → 结算费用 → 银行入账”。
3. 收集境内发票、境外 invoice/receipt、合同、付款证明和内部审批，形成凭证包。
4. 登记收入、成本、资产、应收应付、渠道手续费和汇兑差额；异常进入差异表。
5. 按电子税务局当次待办和税种认定准备申报草稿，经办与复核分离后提交。
6. 归档申报回执、缴款凭证、银行对账单、余额调节表和月结结论。
7. 更新 `operations.json` 的观察时间、状态、证据引用与下一动作，不删除历史证据。

## 4. 决策边界

- 文档提供控制框架，不构成税务、法律或审计意见。金额变大、跨境付款、税种变化、
  关联交易或住宅费用扣除前，向湖北主管税务机关、开户行或执业会计师核实。
- “能登录”不等于获授权提交。报税、转账、退款、开票、备案和商户配置必须由用户
  明确确认具体动作。
- 不为了做成本而制造缺乏真实性、合法性或关联性的凭证；证据不足时先挂待核实或
  作为不可税前扣除处理。
