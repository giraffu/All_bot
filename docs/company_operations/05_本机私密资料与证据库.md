# 本机私密资料与证据库

## 1. 目录契约

默认根目录为：

```text
${XDG_CONFIG_HOME:-~/.config}/allbot/company-operations/
├── identity.json             # 主体详情、账号标识、账户尾号
├── credentials.json          # 登录名、密码、支付密码、恢复渠道
├── hardware-secrets.json     # E 盾/硬件认证 PIN 与实物保管元数据
├── operations.json           # 当前申报、备案、商户和安全待办
├── evidence/                 # 证照、截图、回执、账单原件及索引
├── ledger/                   # 流水、费用、税务、对账、供应商 CSV 与派生导出
└── accounting/
    ├── logs/                 # 逐月记账/结账操作日志；具体金额和凭证号只在这里
    ├── inbox/                # 待导入的银行、渠道、订单、发票和股东原始资料
    └── historical/           # 已退出当前事实源的旧工作簿或迁移快照
```

根目录和子目录必须为 `0700`，JSON、CSV 和原始证据为 `0600`，owner 是当前本机用户，
不允许符号链接。运行：

```bash
python3 scripts/company_operations_vault.py check --json
```

校验器只报告存在性和权限，不输出 JSON 内容。不要用 `cat`、shell tracing、完整
Compose 渲染、聊天粘贴或截图来“验证”密码。

## 2. 保存与读取规则

- 普通知识查询只读 `operations.json` 的非秘密状态；只有明确登录/配置任务才按字段
  读取 `credentials.json`，且不在回答、日志或命令行参数中回显。
- 银行登录密码、支付密码和 E 盾 PIN 分文件保存；经办与复核账号分别登记，避免一个
  自动化流程同时持有两种操作权。
- 支付宝 RSA2 私钥和生产证书仍由部署环境 secret 投影管理。保险库只存 `secret_ref`、
  公钥/证书指纹、owner、轮换时间，不存第二份私钥。
- 发现同一密码跨多个账户复用时在 `operations.json.security_findings` 建高优先级轮换
  任务；不得自动改密，以免锁死税务、银行或支付恢复链路。
- 秘密需要交给程序时使用 stdin、受保护文件描述符或目标 secret store，不使用 shell
  参数、环境 dump 或临时明文文件。

当前实现是“本机明文 + Unix 权限”，能防止误提交和普通用户读取，但不能抵御 root、
恶意软件、被盗磁盘或账号失陷。需要异地备份时先使用独立密钥加密，再保存密文；不把
明文目录同步到 iCloud、网盘、Git 或附件系统。

## 3. 证据归档

原件按 `company/`、`tax/`、`bank/`、`alipay/`、`wechat/`、`vendors/`、`website/`
分类。`evidence/index.json` 为每个文件记录：

- 相对路径、SHA-256、MIME 类型、取得时间、来源平台/提供人；
- 证据期间、关联账号/申报/业务单、是否含秘密；
- 原件状态、替代文件和备注。

导入时复制原件并设为 `0600`，不裁剪、不压缩、不覆盖；需要标注或 OCR 时另存派生件，
并回链原件哈希。无法访问的聊天/macOS 临时路径只登记“待重新导入”，不能声称已归档。

## 4. 账务操作日志

具体记账过程使用 `accounting/logs/YYYY-MM/YYYY-MM-DD_<主题>.md` 或同等结构的 JSON
单独归档，不写入 Git 文档。每份日志至少记录：

- 观察时间、账套/会计期间、操作人、软件状态和结账状态；
- 原始证据引用及其是否已经导入保险库，不能访问的临时路径标记为待导入；
- 业务事件、凭证号、借贷科目、金额、附件和更正原因；
- 银行、渠道、在途、往来、预收、税费、收入费用的期末核对；
- 利润表、资产负债表和试算平衡结果，以及未决税务/缺票/跨期事项；
- 下一动作、经办/复核和后续完成证据。

日志可以保存真实金额、凭证号和脱敏账户引用，但不能保存密码、支付口令、E 盾 PIN、
验证码、私钥或完整敏感账号。日志只追加更正段落，不覆盖原结论；附件以相对路径和
SHA-256 索引，云财务中的凭证/报表仍是账套事实源。

稳定知识与运行记录的边界如下：

| 内容 | 保存位置 |
| --- | --- |
| 通用科目含义、分录模式、月结门禁 | Git `docs/company_operations/` |
| 当月金额、余额、凭证号、截图、点击过程 | 私密 `accounting/logs/` |
| 银行/渠道/发票/回执原件 | 私密 `evidence/` 或 `accounting/inbox/` |
| 可重建的勾稽表和脱敏汇总 | 私密 `ledger/exports/`，并回链原件 |
| 当前申报/备案/商户待办 | 私密 `operations.json` |

## 5. 恢复清单

每个高价值账户记录官方入口、绑定手机/邮箱的脱敏标识、恢复材料、客服电话、开户行、
E 盾/印章/营业执照实物位置和替代管理员。恢复文档不保存短信验证码或一次性会话。
遗失 E 盾、设备或疑似泄露时先冻结相关权限，保存事件时间线，再按银行/平台官方流程
挂失与轮换。
